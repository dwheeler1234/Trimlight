# Trimlight Home Assistant Integration
![Trimlight icon](assets/icon.png)

Home Assistant custom integration for Trimlight EDGE lights.

This integration uses the Trimlight EDGE cloud API and adds Home Assistant entities for power, brightness, built-in presets, saved custom presets, custom effect modes, speed control, and current preset tracking.

This is a custom integration, not an official Home Assistant integration.

## Features

- [Controller schedules and playlists](docs/schedules-playlists.md): daily enable switches, calendar schedule CRUD, combined effects, configuration sensors and Home Assistant actions
- [Controller/account management](docs/controller-management.md): discovery, operating mode, connectivity/firmware/clock diagnostics, preset CRUD, native groups, overlays, controller configuration and backup/restore actions
- Custom pattern draft editor with 30 entries, RGB colors, pixel counts, disabled entries, animation mode, preview, and save-as-new
- RGB color picker on `light.trimlight` (temporary solid-color preview)
- `number.trimlight_effect_length` for built-in pattern length (1-90)
- `switch.trimlight_reverse_animation` for built-in animation direction
- UI-based setup through Home Assistant config flow
- `light.trimlight` for power and brightness
- `select.trimlight_built_in_preset` for built-in animations
- `select.trimlight_custom_preset` for saved custom presets
- `select.trimlight_custom_effect_mode` for custom effect modes
- `number.trimlight_effect_speed` for effect speed as a 0-100% slider
- `sensor.trimlight_current_preset` with effect detail attributes
- `button.trimlight_refresh_presets` to refresh preset caches
- Local preset cache written to your Home Assistant config directory
- Optional structured debug logging for troubleshooting

## Requirements

You need:

- A Trimlight EDGE controller
- A Home Assistant installation that supports custom integrations
- `client_id`
- `client_secret`
- `device_id`

The integration validates the credentials during setup by calling the Trimlight device-detail endpoint.

### Credential Details

- `client_id`
  The Trimlight EDGE account identifier used by the API. In your setup, this is the same value you have already been using in your Trimlight EDGE scripts.
- `client_secret`
  The Trimlight EDGE API secret. This is not generated by Home Assistant. It must come from Trimlight or from the credentials already used by your existing Trimlight EDGE tooling.
- `device_id`
  The unique device identifier for your Trimlight EDGE controller.

If you already have working Trimlight EDGE scripts, reuse the same `client_id`, `client_secret`, and `device_id` values here.

If you do not know your `device_id`, use your existing Trimlight scripts or other Trimlight EDGE tooling to fetch it before adding the integration.

## Installation

### HACS

This repository uses the HACS integration layout and includes `hacs.json`.
HACS requires a **public GitHub repository**; a private repository cannot be
installed by adding its URL, even when it belongs to your GitHub account.

Before the first HACS installation, the repository owner must make the reviewed
repository public and merge the feature pull requests into `main` in order:
#1 (pattern editor), #2 (controller management), then #3 (schedules/playlists).
The feature code is already pushed on GitHub, but an unmerged branch is not what
a normal repository-link installation downloads. Without a published GitHub
release, HACS downloads the default branch. This is a beta for Home Assistant
and physical-controller testing; offline tests do not establish hardware support.

Once those publishing steps are complete:

1. Open **HACS > three-dot menu > Custom repositories**.
2. Enter `https://github.com/dwheeler1234/Trimlight`.
3. Select **Integration**, then **Add**.
4. Find **Trimlight** and select **Download**.
5. Restart Home Assistant, then add **Trimlight** under **Settings > Devices & Services**.

For updates, use HACS **Update information** and **Redownload** if needed, then
restart Home Assistant. Back up your existing integration before the first beta
installation. No GitHub release has been published by these instructions.

HACS installs both the backend and the bundled pattern-card JavaScript under
`custom_components/trimlight`. No separate file copy is required. Add the dashboard
resource and card using the Custom Pattern Editor instructions below.

### Manual Installation

1. Open your Home Assistant config directory.
2. Create `custom_components/trimlight` if it does not already exist.
3. Copy the contents of [`custom_components/trimlight`](custom_components/trimlight) into your Home Assistant config at `custom_components/trimlight`.
4. Restart Home Assistant.

For local development, direct copy into the Home Assistant config folder is the fastest workflow. You do not need HACS `Redownload` if you are copying files directly.

## Configuration

After installation:

1. Go to `Settings` -> `Devices & Services`.
2. Select `Add Integration`.
3. Search for `Trimlight`.
4. Enter:
   - `client_id`
   - `client_secret`
   - `device_id`

The integration creates a config entry titled `Trimlight <last 6 chars of device_id>`.

## Options

The integration exposes these options in the options flow:

- `Commit custom presets`
  When enabled, updates to a saved custom preset are written back to that saved preset and then re-run by ID. This is most useful for custom speed and brightness changes that you want to persist.
- `Enable debug logging`
  Writes structured JSONL debug events to `trimlight_debug_ENTRY_ID.jsonl` in your Home Assistant config directory.

## Entities

The integration creates these entities:

- `light.trimlight`
  Power and brightness control
- `select.trimlight_built_in_preset`
  Built-in Trimlight animations
- `select.trimlight_custom_preset`
  Saved custom presets from the controller
- `select.trimlight_custom_effect_mode`
  Effect mode for the active custom preset
- `number.trimlight_effect_speed`
  Effect speed displayed as 0-100%
- `sensor.trimlight_current_preset`
  Current preset name plus effect detail attributes
- `button.trimlight_refresh_presets`
  Refresh preset lists from the controller

### Sensor Attributes

`sensor.trimlight_current_preset` exposes:

- `current_effect_id`
- `current_effect_category`
- `current_effect_mode`
- `current_effect_speed`
- `current_effect_brightness`
- `current_effect_pixel_len`
- `current_effect_reverse`
- `current_effect_pixels`

For saved custom presets, the integration prefers the saved preset definition over stale controller data when it can safely identify the active preset.

### Select Entity Attributes

The select entities expose extra lookup attributes:

- `select.trimlight_custom_preset`
  - `current_id`
  - `presets`
  - `name_to_id`
  - `option_to_id`
- `select.trimlight_built_in_preset`
  - `current_id`
  - `builtins`
- `select.trimlight_custom_effect_mode`
  - `current_mode_id`
  - `modes`

## How The Integration Behaves

### Data Updates

- The integration is `cloud_polling`.
- Standard polling interval is `600` seconds.
- After control actions, the integration schedules a verification refresh after `5` seconds.
- Power transitions use a `20` second grace window to reduce UI flicker while the controller settles.

### Power And Brightness

- `light.turn_on` sets the controller switch state to `1`.
- `light.turn_off` sets the controller switch state to `0`.
- Brightness updates are applied to the active effect.

### Built-In Presets

- Built-in presets are selected with `select.trimlight_built_in_preset`.
- If the controller is off, the integration powers it on first.
- The integration tries the built-in preview path first.
- If the controller rejects the built-in preview shape, the integration falls back to the saved built-in effect by ID.
- If the first selection does not stick, the integration may reapply the built-in automatically during verification.

### Custom Presets

- Saved custom presets are selected with `select.trimlight_custom_preset`.
- The integration applies saved custom presets by ID.
- If the controller is off, the integration powers it on first and then applies the preset.
- If the first selection does not stick, the integration may re-run the preset automatically during verification.
- Duplicate custom preset names are disambiguated in the selector, for example `Name (id 12)`.

### Custom Effect Modes

- Custom effect modes are selected with `select.trimlight_custom_effect_mode`.
- The mode list comes from the built-in `CUSTOM_EFFECT_MODES` map in the integration.
- Mode changes apply to the active custom effect.

### Speed Control

- `number.trimlight_effect_speed` displays speed as `0-100%`.
- The integration converts that to the device's `0-255` speed range.
- Built-in speed changes are applied to the active built-in effect.
- Custom speed changes are applied to the active custom effect.
- When `Commit custom presets` is enabled, custom speed changes are persisted back to the saved custom preset before the preset is re-run.

### Startup And Off-To-On Behavior

- After powering on from an off state, `Custom preset` and `Custom effect mode` may briefly show `unknown` or remain blank while the controller reports its active effect.
- This short delay is expected.
- The `Current preset` sensor, custom select, and custom effect mode should settle once the controller state catches up.

### Preset Cache

Preset cache data is stored in Home Assistant storage and also written as a readable file in your Home Assistant config directory:

- `trimlight_presets_<entry_id>.json`

If built-in presets are not returned by the controller, the integration falls back to the static built-in preset list bundled with the integration.

## Automation Examples

### Custom Pattern Editor

The [Trimlight-style custom card](www/trimlight-pattern-card.js) follows the app's
layout: a circular color palette, six-column pattern grid with counts inside the
circles, an expandable 30-entry view, a pattern dropdown, animation mode, and
brightness/speed sliders. Backgrounds, panels, text, borders, and accents inherit
the active Home Assistant theme. Circle fills show the actual RGB pattern colors.
Drag any fixed or custom palette color onto a pattern circle to apply it directly.
Color drops preserve all light counts, including zero. Drag the X disable control onto a slot to disable it while preserving its color
and light count. Clicking X still disables the selected slot. Native drag-and-drop requires browser support; selecting a
slot and clicking a palette color remains available on touch devices.
Click a pattern circle to select it and open its light-count dialog (0-60).
Drag palette colors or X directly onto slots without opening the dialog. Changing
a populated slot's color preserves its count.
The UI numbers entries 1-30; their underlying API indexes are 0-29.

To install the matching card (HACS or manual integration installation):

1. Download/update Trimlight to **0.2.0-beta.10** or newer and restart Home Assistant.
2. Add `/trimlight/trimlight-pattern-card.js?v=0.2.0-beta.10` under **Settings >
   Dashboards > Resources** as a **JavaScript module**. If the Resources menu is
   hidden, enable Advanced Mode in your user profile. Remove the previous
   `/local/trimlight-pattern-card.js` resource if you installed it manually; use
   only one resource for this card. Reload the browser after changing resources.
3. Add a Manual dashboard card with:

   ```yaml
   type: custom:trimlight-pattern-card
   title: Trimlight
   ```

Use [the full card configuration](docs/trimlight-pattern-card.yaml) for entity
ID overrides if your controller entities have different names or suffixes.
The card is listed as **Trimlight Pattern Editor** in the card picker once the
resource loads; downloading an integration does not add a dashboard card for you.
For dashboards with YAML-managed resources, add the same URL with `type: module`
to your Lovelace resources configuration instead of using the Resources UI.

The JavaScript is bundled in `custom_components/trimlight/frontend` and is served
at the URL above during integration setup, before controller authentication.
There is no file to copy into `/config/www`. Missing editor entities still require
successful backend setup; check the Trimlight logs if the connection fails.
If the browser shows “Custom element doesn't exist”, check that the resource URL
opens JavaScript and then hard-refresh the browser. On future updates, change the
resource's `v` query value to the installed integration version if it stays cached.

The custom card requires the editor backend in this integration; installing the
JavaScript file alone does not create the entities. It runs without external
JavaScript dependencies or a separate frontend plugin. The palette includes
warm-white and black as RGB values; it does not add a dedicated white channel.
Selecting a color for an empty entry gives it a count of one. **X** disables the
selected entry. The pattern dropdown loads a saved definition locally and never
starts it on the lights.

Click a position circle to select it and open a themed pixel-count dialog. Enter
a whole number from 0 to 60 and press **Save**, or cancel/Escape to keep its count.
The dialog preserves typed input during incoming state updates. Palette choices
still apply to the selected position after closing the dialog.

The **Pattern name** dropdown loads existing patterns into the draft. **New**
prompts for a name before starting a fresh draft, and **Save new** prompts for the
name of the saved copy. Cancelling either prompt leaves the draft and saved
patterns unchanged. The current draft name is displayed below the position grid.

The palette has four rows of seven circles. The top three rows always remain
visible; its expand/collapse arrow shows or hides only the fourth row, initially hidden.
The two rightmost circles in row two and all circles in the bottom two rows are
16 custom-color slots. Tap a custom circle to apply its color; tap its pencil
to choose a new RGB color and apply it to the selected pattern position. Custom
colors persist in this browser's local storage, separately for each configured
pattern-name entity. They are not shared between browsers/devices; if browser
storage is disabled they remain available only in memory for this card session.

For a standard-card alternative, use the [entity-based dashboard card](docs/custom-pattern-editor.yaml),
which needs no JavaScript resource.

1. Press **New Pattern**, or select a saved custom preset with the existing
   custom-preset selector, wait for selection to finish, and press **Load Current Pattern**.
2. Enter a name and choose the draft animation mode, speed and brightness.
3. Choose **Pattern Entry** (0-29). Set **Pixel Count** (0-60), choose its RGB
   color, and toggle **Entry Disabled**. Repeat for the other entries.
4. Press **Preview Pattern** to turn on the controller in manual mode and run
   the draft without saving it.
5. Press **Save New Pattern** to create a new saved preset. Select that preset
   with the existing custom-preset selector when you want to run the saved copy.

Editing fields, starting a new draft, and loading a pattern do not control the
lights. The draft color-picker's power toggle only enables/disables the selected
entry; its brightness slider changes the whole draft's brightness. A zero count
omits an entry's contribution, while disabled entries retain their counts and
colors for editing. Indexes identify pattern entries, not individual physical
roof pixels or independent zones. At least one enabled, nonzero entry is needed
for preview/save. The mode selector uses the documented modes 0-16.

Each **Save New Pattern** press requests a new saved preset (the controller allows
up to 60 saved effects). It does not overwrite the source, even if the name is
unchanged or `Commit custom presets` is enabled. Saving alone does not turn on or
run the saved copy. A save error is reported without adding a local preset; if
the controller accepts a save without returning its ID, refresh the preset list
before trying again. A network timeout can likewise leave the save outcome
unknown; check the controller before retrying to avoid duplicate copies.

Drafts are per controller and stay separate from incoming state polls. They are
held in memory and reset on integration reload/restart. The pattern name entity
exposes `pixels`, `mode`, `speed`, `brightness`, `selected_index`, and
`last_saved_id` attributes for dashboard previews and automations. For offline
editor regression tests, run `python tools/test_pattern_editor.py`.
Run `node tools/test_pattern_card_logic.cjs` for offline card-logic checks. For
browser/layout checks on a development machine with Playwright and a browser
installed, run `node tools/test_pattern_card.cjs` (or add `--channel=msedge` on
Windows). Browser tests use a simulated `hass` object and do not control real lights.
`node tools/build_pattern_preview.cjs` creates a standalone HTML preview with
sample state and light/dark theme buttons.

### Choose A Solid Color

```yaml
action: light.turn_on
target:
  entity_id: light.trimlight
data:
  rgb_color: [255, 80, 0]
  brightness_pct: 70
```

Choosing a color replaces the running effect with a temporary static custom preview.
It does not overwrite a saved preset, even with `Commit custom presets` enabled.
Brightness/speed changes to an unsaved custom preview keep it unsaved. Select a
built-in or saved custom preset to return to an animation. RGB state is reported
only when the active static custom pattern has one enabled color throughout;
multicolor patterns and built-in effects have no single reported RGB color.

### Adjust A Built-In Animation

After selecting a built-in preset and allowing its verification to finish:

```yaml
action: number.set_value
target:
  entity_id: number.trimlight_effect_length
data:
  value: 40
```

```yaml
action: switch.turn_on
target:
  entity_id: switch.trimlight_reverse_animation
```

These two controls are available only for a settled built-in effect running in
manual mode. They preserve its mode, speed, brightness and other parameter.
Changes use preview and do not overwrite a saved effect. They are unavailable
while off, in timer mode, during a pending preset transition, or while a custom
effect runs. Actual visual direction/length behavior depends on the animation.
Entity IDs may have suffixes if several controllers are configured.

## Troubleshooting

- If custom presets do not appear, press `button.trimlight_refresh_presets`.
- If HACS appears to show an older commit, use `Update information` before `Redownload`.
- If the current preset is briefly `Unknown` or `Off` during a transition, wait for the verification refresh to complete.
- If you are testing local code by copying directly into Home Assistant, restart Home Assistant after each integration change.
- If you enable debug logging, review `trimlight_debug_ENTRY_ID.jsonl` in your Home Assistant config directory.
- The integration expects valid Trimlight EDGE API credentials for every request. Invalid credentials will cause setup or refresh failures.

### Pixel Preview

This markdown card renders a simple 6x5 preview grid using `current_effect_pixels` from `sensor.trimlight_current_preset`.

```yaml
type: markdown
title: Preview
content: >
  {% set pixels =
  state_attr('sensor.trimlight_current_preset','current_effect_pixels') or []
  -%} {% if pixels -%} <table
  style="border-collapse:collapse;border-spacing:0;line-height:0;"> {%- for row
  in range(0,6) %} <tr style="line-height:0;"> {%- for col in range(0,5) %} {%-
  set i = row*5 + col %} {%- set p = (pixels | selectattr('index','equalto', i)
  | first) %} {%- if p is none %} {%- set color = 0 %} {%- set count = 0 %} {%-
  else %} {%- set color = p.color | int %} {%- set count = p.count | int %} {%-
  endif %} {%- set r = color // 65536 %} {%- set g = (color // 256) % 256 %} {%-
  set b = color % 256 %} {%- set hex = '%02X%02X%02X' % (r,g,b) %} <td
  style="width:28px;height:28px;padding:0;text-align:center;vertical-align:middle;">
    <font color="#{{ hex }}" style="line-height:28px;display:inline-block;"><b>{{ count }}</b></font>
  </td> {%- endfor %} </tr> {%- endfor %} </table> {%- else %} No pixel data {%-
  endif %}
```

### Pixel Details

```yaml
type: markdown
content: >
  {% set pixels =
  state_attr('sensor.trimlight_current_preset','current_effect_pixels') %} {% if
  pixels %} <div style="font-family: monospace; white-space: pre-wrap;
  word-break: break-word;"> {% for p in pixels %} {% set color = p.color | int
  %} {% set r = (color // 65536) %} {% set g = (color // 256) % 256 %} {% set b
  = color % 256 %} {% set hex = '%02X%02X%02X' % (r, g, b) %} <div>idx {{
  p.index }} | count {{ p.count }} | disable {{ p.disable }} | <span
  style="color: rgb({{ r }}, {{ g }}, {{ b }}); font-weight: 600;">
    <font color="#{{ hex }}">{{ color }} (#{{ hex }})</font>
  </span> </div> {% endfor %} </div> {% else %} No pixel data {% endif %}
```

## Automated Test Runner

This repository includes a Windows-friendly test runner for state-based validation:

- [`tools/trimlight_test_runner.py`](tools/trimlight_test_runner.py)
- [`tools/run_trimlight_tests.ps1`](tools/run_trimlight_tests.ps1)
- [`tools/trimlight_test_runner.example.json`](tools/trimlight_test_runner.example.json)

Recommended setup:

1. Copy `tools/trimlight_test_runner.example.json` to `tools/trimlight_test_runner.local.json`.
2. Create a token file such as `tools/ha_trimlight.token`.
3. Paste your Home Assistant long-lived token into that file.
4. Edit the local config file with your Home Assistant URL, share path, and preset names.
5. Run the suite:

```powershell
.\tools\run_trimlight_tests.ps1
```

Useful commands:

```powershell
.\tools\run_trimlight_tests.ps1 -Scenario custom_off_to_on
python .\tools\trimlight_test_runner.py --list-scenarios
```

Runner output is written to the local `debug/` folder. When available, the runner also copies the latest `trimlight_debug_*.jsonl` file from your Home Assistant share into `debug/`.
